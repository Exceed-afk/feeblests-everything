# Calculator Overlap Report

`src/shared/calculators.ts` (and the loan math in `src/shared/tools-math.ts`) pre-date the
all-in-one calculator. They power the old **Calculator page** (`src/renderer/src/modules/Calculator.tsx`,
an eight-card single page still reachable in the code, though the registered tool in
`src/renderer/src/tools.ts` now points at `CalculatorTool.tsx`) and the **Tools hub**
(`src/renderer/src/modules/ToolsHub.tsx` → `src/shared/tools-math.ts`). The new calculator core
lives in `src/shared/calculator/modules/`. This note maps the old functions onto the new ones,
compares real outputs, and recommends what to do with each.

Verified by running both implementations side by side (`tsx`, decimal.js `Decimal` vs `number`).
The comparison script itself is `scripts/tmp-overlap-compare.ts` — a throwaway, not part of `npm test`.

## Summary of differences found

No case was found where the two implementations give _materially different_ answers for the same
valid input. The differences are of two kinds, neither a bug:

1. **Precision**: the old functions use `number` (float); the new core uses exact decimals. Examples:
   `convertCurrency(100, 1.0875)` → old `108.74999999999999`, new `108.75` exactly.
   The new value is the mathematically correct one; the old one differs by float noise only.
2. **Invalid-input handling**: the old functions return `null`; the new core throws `CalcError`
   with a message. Same semantic ("cannot do that"), different mechanism.

Two interface differences worth knowing (also not bugs, but a porting hazard):

- **Rate units**: old `loanPayment` / `compoundInterest` take an **annual percentage** (5.25 = 5.25%),
  while the new `tvm` / `compoundInterest` take a **rate per period / decimal rate**
  (`5.25/12 %` per month, `0.0525` per year). `loanAmortization` also expects the decimal annual
  rate — passing the percentage produced nonsense in testing (payment $87,500/mo on a $200k loan).
- **Money units**: `tools-math.ts` works in integer **cents**; the new finance module works in the
  number itself.
- The new `tip(bill, tipRate, people)` returns `perPerson` unsplit in one observed call shape
  (`tip(85.4, 0.18)` → `perPerson 100.772`): its `people` parameter must be passed, the old
  `tipSplit(bill, tipPercent, people)` required it too but returns per-person always divided.

## What the old modules do that the new core does not

- `UNIT_OPTIONS` includes volume units (`tsp`, `tbsp`, `cup`, `pt`, `qt`) and old-style ids that the
  new `UNIT_CATEGORIES` names differently; the new module instead adds **data, time, pressure**
  categories and knots. Neither set is a superset; porting the old card 1:1 is not mechanical.
- `CURRENCIES` (12 fixed codes) constrains the old currency card. The new calculator stores
  free-text 3–5 character codes in `calc_rates`, so it is strictly more permissive.
- `tools-math.ts` extras with no new-core equivalent: `addMonthsClamped` is used for payoff dates
  in the Tools hub; the new datetime module has `addDateInterval` with clamping, so this one _is_
  replaceable, but nothing is broken.

## Recommendation summary

- **Leave alone**: everything. No old function gives a wrong answer for its own contract, and
  callers (old Calculator page, Tools hub) depend on the float/cents behaviour.
- **Delete later**: `src/shared/calculators.ts` and the loan half of `src/shared/tools-math.ts`
  become dead code only when the old single-page `Calculator.tsx` is retired (the registered tool
  already uses `CalculatorTool.tsx`; the old file remains imported by `tests/calculators.ts`).
- **Do not** make thin wrappers now: the rate-unit (percent vs decimal) and cents-vs-decimal
  differences mean a wrapper would have to convert units, which is more risk than value while both
  surfaces are live.
- `round8` in `src/shared/math.ts` is unrelated to the calculator and stays.
